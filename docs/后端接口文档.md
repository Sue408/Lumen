# Lumen 后端接口文档（前端使用）

> 面向前端的 Rust 后端契约说明。所有 IPC 通过 `@tauri-apps/api/core` 的 `invoke` 调用，事件通过 `@tauri-apps/api/event` 的 `listen` 订阅。命令名与参数保持 Rust 侧原样。

## 约定

- **DTO 命名**：Rust 侧统一 `#[serde(rename_all = "camelCase")]`，前端拿到的是 camelCase 字段。
- **时间**：一律 RFC3339 字符串（UTC，如 `2026-09-10T11:08:05+00:00`）。
- **金额**：USD，`number`，网关按「每百万 token」单价计算，保留 6 位小数。
- **端口 / 地址**：默认 `127.0.0.1:8787`，仅绑回环；网关默认关闭，由前端显式启停。
- **错误**：命令返回 `Result<T, AppError>`，失败时 Promise reject，值为字符串（`AppError` 序列化为字符串），直接用 `String(err)` 展示即可。
- **浏览器回退**：非 Tauri 环境（`pnpm dev`）应走 mock；本项目已在 `src/services/gateway.ts` 用 `isTauriRuntime(window)` 做守卫，新增接口沿用同一模式。

## 2. 命令一览

### 网关生命周期

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `gateway_status` | — | `GatewayStatus` | 当前运行状态与地址 |

```ts
await invoke<GatewayStatus>("start_gateway");
await invoke<GatewayStatus>("stop_gateway");
const status = await invoke<GatewayStatus>("gateway_status");
```

### 用量统计

| 命令 | 参数 | 返回 |
|---|---|---|
| `query_usage_overview_cmd` | `{ period: PeriodKey; anchor?: string \| null; virtualKeyId?: string \| null }` | `UsageOverview` |

- `anchor`：RFC3339 时间串，用于查询任意历史周期；省略则取当前时间。
- `virtualKeyId`：分户口径。省略或 `null` = 全部；字符串 `"__unassigned__"` = 历史无归属流量；其余为密钥 id。它同时决定 `layers` 的堆叠维度：全部 → 按密钥；单 key / 未归属 → 按模型。
- `series` 为**累计值**（单位：万 token），与 `src/features/usage/usageVisualData.ts` 的 `cumulativeToDistribution` 配套使用。
- `day` 桶为 24 个小时点，`week` 为 7 天，`month` 为当月天数；前端可 `resampleSeries` 到可视点数。
- `layers` 为**累积花费**（元），按金额取前 4 层 + 「其他」；「未归属」与「其他」的 `tone` 为 `ink`（墨阶，不占矿物颜料）。
- `attribution` 为一句话归因的结构化因子；`quality` 为命中率 / 失败率 / 推理占比。失败率覆盖全部记录（含失败与估算）；命中率与推理占比只统计有上游上报细节的记录，排除 `estimated`（估算值不携带缓存 / 推理字段，混入会稀释真实比率）。
- `modelCosts` 至多 4 条，末位为「其他」，`tone` 按排名映射到矿物颜料 token。

```ts
const overview = await invoke<UsageOverview>("query_usage_overview_cmd", {
  period: "week",
  anchor: new Date().toISOString(),
});
```

#### 用量与计费语义（准确度约定）

- **缺失不等于 0。** 上游未返回的字段在日志里是 `0` 但可能伴随 `usageSource="missing"`；展示时应区分「确实是 0」与「没有数据」，不要用数值直接推断。
- **`usageSource`**：`provider` 可直接结算；`estimated` 表示上游漏报或只报部分，网关用请求 / 响应文本估算（按模型匹配 tokenizer，未收录的模型回退字符启发式）并计入 `cost`；`partial` 表示流未收尾（例如客户端中断、上游未返回末块），数值是已累积的真实量但不完整；`missing` 表示上游未返回任何用量且估算也拿不到文本，`cost` 记为 0。
- **缓存计费**：`cacheReadTokens` 是否已含在 `inputTokens` 由协议决定，并由 `cacheReadInInput` 显式记录——OpenAI / DeepSeek / Responses / Gemini 为 `true`（计费前扣除命中），Anthropic 为 `false`（分别按 `cacheReadPrice` / `cacheCreationPrice` 计价）。缓存价配为 `0` 时回退输入价，避免命中被算成免费。
- **缓存命中率**：`quality.cacheHitRate` 的分母按 `cacheReadInInput` 归一——`true` 时 `input + cacheCreation`，`false` 时 `input + cacheRead + cacheCreation`；分子恒为 `cacheRead`。这样 OpenAI 系不会因命中已含在输入中而被重复计入分母、低估命中率。命中率与推理占比另排除 `usageSource="estimated"` 的记录——估算值不携带缓存 / 推理字段，混入会稀释真实比率。
- **`modelReal`** 是真正发给上游的模型名；`upstreamModelName` 只是展示名。对账请用 `modelReal`。
- **流式**：网关对 OpenAI 协议自动向上游注入 `stream_options.include_usage=true`（客户端已显式设置时尊重其值），以保证末块带回完整用量。

### 遥测与连通性

| 命令 | 参数 | 返回 |
|---|---|---|
| `query_telemetry_cmd` | `{ period?: "day" \| "week" \| "month"; anchor?: string \| null }` | `TelemetrySnapshot`（吞吐 / 生成速度 / 被动连通性 / 冷却中模型） |
| `test_provider_cmd` | `{ providerId: string }` | `ProbeResult`（对提供商名下首个启用模型发一次最小消息请求；**不写日志、不计费、不触发冷却**） |

- `throughput` 随 `period` 分桶，与用量总览的日 / 周 / 月桶对齐：日 = 24 个整点桶、周 = 7 个天桶、月 = 当月天数个天桶；`tokensPerSec` 为周期平均，分母是**周期起点到现在的已过时长**（当前周期滚动；历史周期已走完，即完整周期时长），`peakTokensPerSec` 为单桶峰值。`anchor`（RFC3339）用于查询历史周期，缺省为当前时间；`period` 缺省为 `day`。
- `generation` 与 `connectivity` 固定为**近 24 小时滑动窗口**，不随 `period` 变化。`generation` 仅统计 `isStream && ttfbMs != null` 的成功记录，升级前的老流水不参与。
- `connectivity` 是**被动口径**：只在有流量时更新，无流量的提供商不会出现在结果里。
- `cooling` 来自网关内存态冷却表，重启即清空。

#### 配置迁移

配置 JSON 只用于**跨设备迁移**，不再用于启动播种：应用启动不会自动导入任何文件，空库首次启动需手动配置或导入。

- 导出范围：`providers`（含明文 `apiKey`）、`upstreamModels`、`routes`（含 `targets`）、`virtualKeys`（含明文 `key`）；**不含**设置、日志、用量。
- 导入为**合并覆盖**：按自然键命中则更新，未命中则新增，未被文件提及的条目**保留**。自然键——provider `name`、upstream model `(provider, modelId)`、route `alias`、virtual key `key`；路由的 `targets` 按 `(routeId, upstreamModelId)` upsert（保留已有 target id）。provider / model 引用既可在文件内新增，也可指向库中已存在的条目，因此支持只含部分条目的增量导入。
- 全程单事务：任一条目校验失败（引用不存在的 provider / model、协议不一致）即整体回滚。
- 明文密钥只落文件，不写日志、不在 UI 回显。

```ts
type ItemSummary = { created: number; updated: number };
type ImportSummary = {
  providers: ItemSummary;
  models: ItemSummary;
  routes: ItemSummary;
  virtualKeys: ItemSummary;
};
```

## 4. HTTP 网关端点（供 Agent 客户端，非前端 IPC）

网关启动后监听 `http://127.0.0.1:<port>`：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/health` | 健康检查 |
| GET | `/v1/models` | 列出**别名**（不暴露上游模型名） |
| POST | `/v1/chat/completions` | OpenAI Chat 兼容；请求 `model` 填别名 |
| POST | `/v1/messages` | Anthropic Messages 兼容直通；用于 Claude Code 等 |
| POST | `/v1/responses` | OpenAI Responses 兼容直通；请求 `model` 填别名 |
| POST | `/v1beta/models/{alias}:{action}` | Gemini 原生直通；模型在路径，`action` 为 `generateContent` / `streamGenerateContent` |

转发规则：`model` 别名 →（按 `priority` 升序得到**有序候选**）→ 逐候选尝试（降级链）；替换 `model` 后按 provider 的 `protocol` / `authScheme` / `extraHeaders` 注入请求头，透传响应与 SSE。

协议绑定：每个路由创建时锁定一个协议，只能从对应端点调用（`openai` → `/v1/chat/completions`，`anthropic` → `/v1/messages`，`responses` → `/v1/responses`，`gemini` → `/v1beta/models/{alias}:{action}`）。路由的所有目标必须与路由协议一致（保存时校验）。端点协议与路由协议不符时，网关返回 `400`，错误体为 `{ "error": { "message": string, "type": "lumen_error", "code": "protocol_mismatch" } }`，**不会转发到上游**，同时落一条 error 日志。

**各协议差异（同协议透传，不做跨协议转换）：**

- **`openai` / `anthropic` / `responses`**：别名取自请求体 `model`，替换后转发到 provider 的上游路径 `chat/completions` / `messages` / `responses`。流式 `openai` 会向上游注入 `stream_options.include_usage=true`（客户端已显式设置时尊重其值）。
- **`gemini`**：别名不在请求体，而在 URL 路径（`/v1beta/models/{alias}:{action}`）；网关把路径重写为 `models/{上游模型}:{action}` 并**不向 body 注入 `model`**。流式动作 `streamGenerateContent` 会向上游追加 `?alt=sse`，因此下游拿到标准 SSE。鉴权用 `x-goog-api-key`。仅支持 `generateContent` / `streamGenerateContent`，其它 `action` 返回 `400`。

**会话维度（只捕获，不合成）**：鉴权通过后，网关照「会话候选头名表」从下游请求头取**第一个非空值**作为 `sessionId`（头名比较大小写不敏感，空串 / 全空白视为未命中）。默认候选表存于 `settings.sessionHeaders`（设置页可改），顺序与覆盖范围：

| 顺序 | 头名 | 覆盖 |
|---|---|---|
| 1 | `x-opencode-session` | OpenCode 自家托管模型 / Go / Zen |
| 2 | `x-session-affinity` | OpenCode 配第三方 provider |
| 3 | `x-session-id` | 通用 |
| 4 | `x-claude-code-session-id` | Claude Code v2.1.86+ |
| 5 | `session_id` | Codex CLI |

会话只是**日志维度，不是实体**：不建表、不做开始 / 结束 / 过期、不做 sub-agent 树、不合成（`fallback=generate` 留待后续）。每次上游尝试的日志都带该值（成功与失败均记，便于按会话追踪失败），客户端未带则为 `null`。按 `(virtualKeyId, sessionId)` 隔离聚合（`list_sessions_cmd`），避免跨密钥碰撞；前端用复合描述（短 id + 首次出现 + 请求数 + 花费）代替不存在的「会话名」。

**请求头映射（per-provider 四意图）**：配置挂在**提供商**上（不是逐个模型），同一 provider 下所有模型共用。网关在把下游请求发往该 provider 时按**固定顺序**求值：

1. **内置底座**：默认放行一批安全头（`user-agent`、`accept-language`、`traceparent`、`tracestate`、`anthropic-version`、`anthropic-beta`、`openai-beta`、`openai-organization`、`openai-project`），开箱即"像直连"；
2. **透传 `forward`**：追加放行客户端头，支持 `*` 通配，**不限定 `x-` 前缀**（如 `session_id` 这类原生头也能放行）；
3. **替换 `replace`**：把客户端头 `from` 以 `to` 的名字写出（有序，后写覆盖先写）；
4. **添加 `extraHeaders`**：常量 `name: value`，覆盖前面的同名头；
5. **移除 `remove`**：按通配删除，**优先级最高**（deny wins），可给底座 / 透传开例外；
6. **硬黑名单**：`host` / `content-length` / `connection` / `transfer-encoding` / `authorization` / `x-api-key` / `x-goog-api-key` **无条件剥离**。

**鉴权头在规则之后无条件注入**（`bearer` / `x-api-key` / `x-goog-api-key`），因此规则无法伪造鉴权、下游虚拟密钥绝不泄漏给上游。保存提供商时按同一套规则校验（`validate_provider_header_rules`），非法规则（空 / 非法字符 / 命中受保护头 / 替换目标带通配）直接拒绝。详见 `docs/网关请求头行为.md`。

> 路由**目标层不再有任何请求头配置**。旧版曾把 `headerRules` 存在 `route_targets` 上，现已停用（列暂留、不再读写）；迁移到 provider 请以提供商为轴重配。

**强制鉴权**：`/v1/chat/completions`、`/v1/messages`、`/v1/responses` 与 `/v1beta/models/…` 必须携带虚拟密钥——`Authorization: Bearer sk-lumen-…`（回退 `x-api-key`；Gemini 原生端点亦接受 `x-goog-api-key`）。缺失、未知或已停用的密钥返回 `401`（`code: "unauthorized"`），不转发上游，并落一条 `virtualKeyId` 为 `null` 的 error 日志。`/health` 与 `/v1/models` 不需要密钥。

**额度闸门**：鉴权通过后，网关按该密钥的 `quotaPeriod` 计算周期起点，累计该周期内成功记录的花费；已达 `quotaLimit` 时返回 `429`（`code: "quota_exceeded"`），不转发上游并落一条带 `virtualKeyId` 的 error 日志。判定在**建连前**完成：并发不锁、流式开流后不撤回，因此**最后一次请求可能略微超出**上限；`quotaLimit` 为 `null` 表示不限。

**降级链（失败切换）**：`model` 解析为按 `priority` 升序的**有序候选**，网关按序尝试；默认粘性——主目标可用就不切换。仅连接失败 / 超时 / 5xx / 429 触发切换；4xx（429 除外）、鉴权失败、内容策略**不**切换，直接透传上游响应。

- **429 分类**：带短 `Retry-After`（≤ 10s）时先等待、**重试同一目标**（保住 prompt cache）；额度类 / 长冷却 / 无信号则切换下一候选。
- **冷却**：切换前把失败目标标记为冷却（429 记 300s、其余 60s；内存态、带过期，重启清空），冷却中的目标在候选过滤阶段被跳过。若全部候选都在冷却中，返回 `502` 并落一条 error 日志。
- **流式**：只在「建连 + 首块到达之前」切换；**首字节发出后不再降级**，只能透传错误。
- **候选耗尽**：透传最后一次尝试的错误响应；若全是连接失败则返回 `502`。
- **记账**：每次上游尝试都落一条日志（`attemptIndex` 递增，记实际履约 target）；失败尝试同样进账，守住「账不低报」。

## 6. 数据库与迁移

- **不再随版本清库**：数据库版本由 `PRAGMA user_version` 记录，启动时按阶梯增量迁移（`db/migrations.rs`），保证 `request_logs` 与 `settings` 跨版本保留。`user_version` 高于本程序支持的版本时**拒绝启动**并提示升级，不做任何破坏性操作。
- **dev / release 数据隔离**：开发构建（`debug_assertions`）使用 `app_data_dir/lumen-dev.db`，发布构建使用 `app_data_dir/lumen.db`。演示数据注入（`inject_demo_cmd`）只在 debug 构建注册，且写入 `lumen-dev.db`，不会污染真实账本。
- **能力标签**：权威词表在后端 `db/models.rs` 的 `MODEL_CAPABILITIES`（`vision` / `tools` / `reasoning`），前端 `providerModel.ts` 的 `capabilityOrder` 为其镜像；保存模型时词表外的取值返回错误。
- **路由目标**：`route_targets` 以 `(route_id, upstream_model_id)` 为唯一键，保存时 upsert，因此 `RouteTarget.id` 稳定；同一路由内重复上游模型被拒。
- **会话列与头规则列**：`request_logs.session_id`（v11）、`route_targets.header_rules`（v12，**已停用**）与 `providers.header_rules`（v13，现行）均为增量列。旧库升级后旧流水 `session_id` 为 `NULL`、旧 provider `header_rules` 为 `{}`，数据不丢。`header_rules` 中的空规则序列化为 `{}`。
- **首字节耗时列**：`request_logs.ttfb_ms`（v14）记录流式请求从上游响应头到达至首个数据块的耗时；非流式为 `NULL`。旧流水的 `ttfb_ms` 为 `NULL`，故升级前的记录不参与生成速度统计。

### 如何写一条迁移

迁移定义在 `db/migrations.rs` 的 `MIGRATIONS`（`[(目标版本, SQL)]`），`configure` 按 `user_version` 逐级执行，每条包一个事务，成功才推进版本。改结构时同步三处：`SCHEMA`（新库建表）、`SCHEMA_VERSION` +1、`MIGRATIONS` 补一条对应目标的语句。

**加列 / 建表 / 建索引（增量，推荐）**

```sql
ALTER TABLE upstream_models ADD COLUMN max_output_tokens INTEGER NOT NULL DEFAULT 0;
```

SQLite `ADD COLUMN` 的限制：不能加 `PRIMARY KEY` / `UNIQUE`；`NOT NULL` 必须带非空默认值；默认值不能是 `CURRENT_TIME` 等；外键列在 `foreign_keys` 开启时必须默认 `NULL`。

**删列 / 改类型 / 去约束（SQLite 不支持直接改，走重建表）**

SQLite 没有「就地改写」引擎，删改列需把整表数据搬到新表：

```sql
CREATE TABLE request_logs_new ( ... 目标结构 ... );
INSERT INTO request_logs_new (id, occurred_at, endpoint, ...)
  SELECT id, occurred_at, endpoint, ... FROM request_logs;
DROP TABLE request_logs;
ALTER TABLE request_logs_new RENAME TO request_logs;
-- 重建原表上的索引（DROP 旧表会连带删除）
CREATE INDEX IF NOT EXISTS idx_request_logs_occurred ON request_logs(occurred_at);
```

- 整段写在**一条**迁移字符串里即可，`apply` 已包事务：失败整体回滚、版本不前进。
- 目标表带外键时：需在事务**外**先 `PRAGMA foreign_keys = OFF`，迁移后再 `ON` 并跑 `PRAGMA foreign_key_check`（`foreign_keys` 是每连接的，且在事务内设置无效）。
- `DROP COLUMN`（3.35+）虽可用，但限制多：不能删 `PRIMARY KEY` / `UNIQUE` / 被索引 / 被外键引用 / 出现在视图、触发器、生成列里的列。
- 必配测试：模拟旧版本库（写入数据 → 把 `user_version` 调低 → 再 `configure`），断言数据保留且版本到位，参考 `db/migrations.rs` 的 `migrates_without_losing_rows` 与 `migrates_from_legacy_version_without_losing_data`（后者从最老版本全链升级，断言行数、金额 SUM 与设置均不丢）。
