# 构建产物体积与运行时性能优化

> 日期：2026-09-12
> 提交：`fe7cc40` perf: shrink release binary via size-tuned profile and trimmed features、`9a20b83` chore: drop unused public assets and modernize the build target、`09f1038` perf: tune the sqlite connection and tween metrics from their current value
> 涉及：`src-tauri/Cargo.toml`、`src-tauri/tauri.windows.conf.json`、`vite.config.ts`、`src-tauri/src/db/mod.rs`、`src/features/usage/metricAnimation.ts`、`src/features/usage/useAnimatedMetric.ts`

## 起因

查询侧已经压过一轮（见《用量总览》《使用日志》两篇）。这次换一个维度：**最终构建产物**——安装包多大、二进制多重、启动与翻页的运行时开销。先量基线，再逐项取舍。

## 一、基线（先量，别猜）

| 产物 | 基线 |
| --- | --- |
| `lumen.exe`（release） | 8.82 MB |
| NSIS 安装包 | 3.32 MB |
| MSI 安装包 | 5.64 MB |
| 前端 JS / CSS | 381.04 / 63.72 KB |
| `target` 构建缓存 | 39.35 GB |

查询基准（debug profile，59,693 行 / 5 密钥）只有 debug 数字：基准依赖 `db::demo::inject_demo`，而它被 `#[cfg(debug_assertions)]` 门控，release 下编不出来。这是**设计如此**（demo 是开发期工具，不进真实构建），不是缺陷；代价是 release 运行时基准缺失，本次以 debug 相对值衡量。

## 二、Rust 二进制：profile 与 feature（`fe7cc40`）

release profile 原本已是 LTO + `codegen-units = 1` + `panic = "abort"` + `strip`，问题只在 `opt-level = 3` 是「性能优先」。

修法不是一刀切降级，而是**分层**：

- 全局 `opt-level = "s"`，让体积大头 webview2 / wry / tao 走尺寸优化；
- 对热路径依赖（`reqwest` / `tokio` / `hyper` / `hyper-util` / `axum` / `tower` / `serde_json` / `rusqlite` / `libsqlite3-sys`）逐条覆写回 `opt-level = 3`。

**不用 `[profile.release.package."*"]`**：那会把 webview2 / wry 也拉回 3，体积收益立刻归零。

另外两处：

- `tokio features = ["full"]` → `["rt-multi-thread", "macros", "net", "sync", "time", "fs"]`。逐个核对源码里的 `tokio::` 用法后收窄，`Cargo.lock` 随之少了 `parking_lot` / `signal-hook-registry`。
- 新增 `tauri.windows.conf.json`，把 Windows 的 `bundle.targets` 收成 `["nsis"]`；mac / linux 仍在主配置里走 `"all"`，跨平台不受影响。这样 Windows 不再下载 WiX、不再产 MSI。

**结果：`lumen.exe` 8.82 → 7.37 MB（−16.4%），NSIS 3.32 → 2.98 MB（−10.2%）。**

## 三、前端：清死资源 + 放宽目标（`9a20b83`）

- 删除 `public/tauri.svg`、`public/vite.svg`、`src/assets/react.svg`——模板残留，无任何引用，却会被原样拷进 `dist`、嵌进安装包。
- `vite.config.ts` 设 `build.target = "esnext"`、保留 `sourcemap` 仅 debug 出。CSS 从 63.72 收到 60.76 KB（−4.6%）。

一个 Vite 8 的现实约束：Vite 8 已换成 rolldown / Oxc，写 `minify: "esbuild"` 会去加载**未安装**的 esbuild，`target: "chrome105"` 也会触发 `vite:esbuild-transpile` 而失败。所以走默认 Oxc 压缩 + `esnext`，不引额外依赖。

## 四、一个被体验否掉的方案：路由懒加载

`App.tsx` 的六个页面全部静态导入，主包 381 KB 里含各页业务代码。曾把六页改 `React.lazy` + `Suspense` 骨架屏：

| 指标 | 静态导入 | 懒加载 |
| --- | --- | --- |
| 主包 JS | 381.04 KB | 206.79 KB（−45.7%） |
| 首屏（usage 视图） | 381 KB | ~245 KB |
| **安装包** | 2.98 MB | 2.99 MB |

**结论：否掉。** 理由：这是本地应用，chunk 从磁盘读、没有网络成本；Tauri 又对嵌入资源做 brotli 压缩，**安装包体积一分没变**。换来的却是每次切页一次 loading 态——KB 级收益买不回体验落差。已回退到静态导入。

教训与查询优化那次相反：那次的教训是「别猜，先量」；这次是「**量出来只是必要条件，还要问收益是否落在用户能感知的地方**」。

品牌图标（`@lobehub` 33 个 SVG，~50 KB raw）本可顺懒加载自动切出去、由 Usage 页推迟到 Providers/Routing，但也随懒加载一起回退了。

## 五、运行时：SQLite 调优 + 动画补间（`09f1038`）

**SQLite**（`db/mod.rs` 的 `open()` 抽出 `tune()`）：

- `synchronous = NORMAL`：WAL 下提交不逐次 fsync，这是逐请求写账热路径的主要收益；崩溃不损坏库，断电可能丢最近若干事务。
- `busy_timeout = 5000`、`temp_store = MEMORY`、`cache_size = -8000`（8 MB）、`mmap_size = 256 MB`。
- 启动 `PRAGMA optimize` 刷新可能过期的优化器统计。

基准是磁盘库（`stats.rs:986` 走 `db::open`），调优确实生效：

| 查询 | 之前 | 之后 |
| --- | --- | --- |
| `COUNT(*)` 无过滤 | 2.46 ms | **0.38 ms** |
| `COUNT usage_source IN(...)` | 0.49 ms | **0.27 ms** |
| `list_aliases` | 11.0 ms | **6.6 ms** |
| Overview 月 | 168.8 ms | **138.9–153.3 ms** |
| Overview 周 | 56.2 ms | 48.8–71.4 ms（噪声大） |

**动画**：`useAnimatedMetric` 原本每次目标变化都从 0 数到新值。抽 `parseMetricValue` / `formatMetricValue` 后，改为从**当前展示值**补间（首次挂载仍 0→目标），消除数据刷新时的重数观感。

## 六、决策与取舍

- **TLS 后端维持 rustls**：`native-tls`（Windows 走 Schannel）本可省掉 `ring` / `rustls` / `webpki-roots`，但会牺牲跨平台（Linux 需 OpenSSL），与「Windows 为主、保留跨平台」冲突，放弃。
- **不设 `[profile.release.package."*"]`**：见 §2，会把体积大头也拉回 3。
- **懒加载否决**：见 §4。
- **`with_db` 合并（网关热路径）搁置**：当前 debug 基准无信号，按 M4「先测量再决定」。
- **`useLiveRevision` 收敛搁置**：它的成本已随查询从 ~118 ms 降到 ~7 ms，再改会削弱实时账本的体感。
- **`opt-level = "s"` 的边界**：全局尺寸优化对极端计算路径有代价，故用热依赖覆写兜住吞吐。

## 七、遗留

- release 运行时基准缺失（demo 门控所致）。若要量 release，需要给基准换独立 fixture，而非放开 demo。
- `build.target = "esnext"` 对 Tauri 的常青 WebView（WebView2 / WKWebView / WebKitGTK）成立；若未来要支持老旧 WebKitGTK，需回退到 `safari13` 并补装 esbuild。
- M4 剩余项：`with_db` 合并、读连接池、rollup 表，均待 50 万 / 100 万行基准触发。
